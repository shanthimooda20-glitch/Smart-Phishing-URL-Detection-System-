# Dataset

The training corpus lives in this directory as `phishing_urls.csv`.

## Expected structure

A CSV with one URL per row and a binary label:

```csv
url,label
nownews.com/n/2017/03/21/2449327,0
awesometime4you.com/wp-admin/js/cmfr/certificatclients.php,1
```

| Column  | Type   | Meaning                                          |
|---------|--------|--------------------------------------------------|
| `url`   | string | The URL. The scheme (`http://`) is optional.     |
| `label` | int    | `0` = legitimate, `1` = phishing / malicious.    |

The loader (`src/ml/train.py`) is deliberately tolerant, so most public
datasets work without editing:

* **Column names** are detected case-insensitively. `url`, `urls`, `link`,
  `domain` and `website` are accepted for the URL; `label`, `isMalicious`,
  `type`, `class`, `status`, `result`, `target`, `phishing` and `verdict` for
  the label.
* **Label values** may be numeric or textual: `phishing`, `phish`,
  `malicious`, `malware`, `bad`, `defacement`, `1`, `true`, `yes` map to 1;
  `legitimate`, `benign`, `good`, `safe`, `clean`, `0`, `false`, `no` map to 0.
  Rows with any other label are dropped.
* **Cleaning** removes empty/short URLs, unusable labels and duplicate URLs
  (duplicates would otherwise leak between the train and test splits).

Drop any dataset matching that shape in as `data/phishing_urls.csv` and run
`python src/ml/train.py` — no code changes needed.

## What ships in this repository

`phishing_urls.csv` — 140,878 URLs, exactly 50/50 legitimate vs. phishing —
is generated by `scripts/build_dataset.py` from two public sources:

1. **URL corpus** — [`incertum/cyber-matrix-ai`](https://github.com/incertum/cyber-matrix-ai)
   (`Malicious-URL-Detection-Deep-Learning/data/url_data_mega_deep_learning.csv`):
   ~195,000 full URLs (host **and** path) labelled `isMalicious` 0/1.
2. **Popular-domain list** — [`zer0h/top-1000000-domains`](https://github.com/zer0h/top-1000000-domains)
   (top 100k), used *only* to top up the legitimate, path-less bucket.

### Why the corpus is re-sampled rather than used as-is

The source corpus carries two collection artefacts that a naive sample bakes
straight into the model:

| Artefact | Effect on a naively trained model |
|----------|-----------------------------------|
| 77% of **path-less** URLs are malicious (the benign half was harvested as full page URLs) | Learns "no path ⇒ malicious" and flags `example.com` |
| The benign half is normalised — bare hosts, no `www.`, few subdomains | Learns "any subdomain ⇒ malicious" and flags `en.wikipedia.org` |

Neither is a property of phishing; both are properties of how the data was
collected. `scripts/build_dataset.py` therefore stratifies on URL **structure**
(path present, and hostname depth) and balances the two classes *inside every
structural bucket*, so the classifier cannot use bucket membership as a
shortcut and has to earn its verdict from the lexical evidence within the
bucket. Bucket budgets are allocated proportionally to the square root of the
available balanced mass, which keeps the dominant "one dot, has a path" bucket
largest while still giving the subdomain buckets enough examples to learn from.

Both effects were observed directly: before the fix, `https://example.com`
scored 82/100 (Phishing) and `https://www.google.com` 58/100 (Suspicious).

### Rebuilding or replacing it

```bash
python scripts/build_dataset.py              # default: every balanced row (~141k)
python scripts/build_dataset.py --rows 40000 # smaller, faster to train
```

Both sources are downloaded at build time; the script needs internet access,
but training and running the app do not.
